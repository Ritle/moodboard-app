# MoodBoards Demo

Автономный frontend-прототип редактора интерьерных мудбордов. Демо предназначено для проверки UX и архитектуры перед интеграцией в существующий сервис с готовым backend.

## Стек и ограничения

- PHP 8.x — страницы, runtime-конфигурация, demo access endpoint и прокси удаления фона;
- JavaScript ES6 modules, jQuery и Konva.js;
- обычный CSS;
- IndexedDB для локальных документов и изображений;
- локальные копии jQuery и Konva, без CDN в runtime;
- Playwright — только dev-зависимость для браузерного baseline, без участия в runtime и сборке.

В проекте намеренно нет Composer, PHP-framework, серверной базы данных, production backend API, React, Vue, Angular и npm build-step. PHP-файлы в `api/` относятся только к демонстрационному доступу и проксированию готового внешнего сервиса удаления фона.

## Размещение

Приоритетная среда — удалённый сервер. Проект публикуется в каталоге сайта `/moodboards`, поэтому публичные ресурсы и страницы используют базовый URL `/moodboards/`.

Основные страницы:

- `/moodboards/index.php` — список мудбордов;
- `/moodboards/editor.php?id={id}` — редактор;
- `/moodboards/view.php?token={token}` — гостевой просмотр по публичной ссылке (`id` временно поддерживается для старых demo-ссылок);
- `/moodboards/repository-smoke-test.php` — изолированная проверка IndexedDB repository.

При открытии списка или редактора выполняется запрос к демонстрационному endpoint `/moodboards/api/mock-user-status.php`. По умолчанию он возвращает авторизованного пользователя тарифа PRO. Тестовый тариф можно выбрать query-параметром:

```text
/moodboards/?mock_tariff=guest
/moodboards/?mock_tariff=free
/moodboards/?mock_tariff=basic
/moodboards/?mock_tariff=premium
/moodboards/?mock_tariff=pro
```

### Специальный технический режим

Query-параметр `mode=view` включает внутреннюю диагностическую панель, скрытую в обычном интерфейсе:

```text
/moodboards/index.php?mode=view
/moodboards/editor.php?id={id}&mode=view
```

Если URL уже содержит query-параметр, используется `&mode=view`. Режим открывает переключатель демонстрационного тарифа и выбор пресета удаления фона. В редакторе также становятся доступны импорт и экспорт полного проекта вместе с assets в JSON. Уведомления и карта слоёв располагаются выше или вне зоны технической панели.

Доступные вспомогательные параметры:

- `mock_tariff=guest|free|basic|premium|pro` — эмуляция тарифного сценария;
- `mock_preset=preset_0|preset_1|preset_01|preset_02|preset_03` — идентификатор серверного пресета удаления фона.

По умолчанию используется `preset_0`. Клиент хранит только отображаемые названия и краткие описания пресетов, передавая выбранный идентификатор PHP-прокси как `preset_id`; модель и остальные параметры определяются удалённым сервисом.

`mode=view` не является публичным гостевым просмотром, не меняет права пользователя и не обходит тарифные, repository или серверные проверки. Публичная страница `/moodboards/view.php?token={token}` остаётся отдельным read-only приложением и намеренно не показывает диагностическую панель.

Доступ к MoodBoards включён для тарифов выше Free: `basic`, `premium` и `pro`; по умолчанию выбран `pro`. `guest` и `free` показывают блокирующий диалог, причём гостю сначала предлагается войти. В хедерах списка и редактора `guest` видит кнопку «Войти», а любой авторизованный пользователь (`free`, `basic`, `premium`, `pro`) — кнопку «Аккаунт». Плавающая настройка «Демо-тариф» переключает сценарии без ручного редактирования URL и остаётся доступной поверх блокирующего диалога. Клиент принимает решение по `is_authorized` и `features.moodboards_allowed`, а `features.max_moodboards` ограничивает создание и дублирование досок.

Для диагностического запуска без сборки откройте терминал в родительском каталоге, содержащем папку `moodboards`, и запустите PHP 8.x:

```bash
php -S 127.0.0.1:8080 -t .
```

Затем откройте `http://127.0.0.1:8080/moodboards/`. Запуск из самой папки проекта без изменения base URL некорректен: публичные пути намеренно начинаются с `/moodboards/`.

Проверка всех PHP-файлов перед публикацией из родительского каталога в PowerShell:

```powershell
Get-ChildItem moodboards -Recurse -Filter *.php | ForEach-Object {
    php -l $_.FullName
    if ($LASTEXITCODE -ne 0) { throw "PHP lint failed: $($_.FullName)" }
}
```

## Конфигурация

Публичная runtime-конфигурация находится в `includes/config.php`. `includes/header.php` только подключает файл и безопасно передаёт массив в `window.MoodboardsConfig`. Здесь настраиваются базовый URL, маршруты, endpoint и ссылки авторизации, минимальная ширина окна, private/public repository drivers, HTTP transport, endpoint удаления фона, а также используемые редактором лимиты листов и истории, параметры autosave, обработки изображений и генерации preview. JavaScript сохраняет fallback-значения для совместимости с неполной конфигурацией.

Файл передаётся в браузер целиком, поэтому в него нельзя добавлять пароли, API-ключи и другие секреты. Серверные секреты будущей интеграции должны читаться из переменных окружения или отдельного файла, который не сериализуется в `window.MoodboardsConfig`.

Список и редактор получают приватный repository через `RepositoryFactory`. Viewer использует отдельный `PublicRepositoryFactory` и минимальный read-only контракт `getSnapshot()`/`getAsset()`, поэтому приватные create/save/archive/delete методы в него не передаются. По умолчанию обе фабрики используют IndexedDB через разные адаптеры. Общие параметры будущего HTTP-транспорта находятся в секции `api`: `baseUrl`, `timeoutMs`, `retryCount`, `csrfToken` и `requireCsrf`. Значение CSRF-токена допустимо передавать только из серверной сессии текущей страницы, а не хранить в репозитории.

`ApiClient` централизует same-origin credentials, JSON, `X-Request-Id`, CSRF, idempotency key, таймаут, ограниченный retry/backoff и нормализацию ошибок. `HttpMoodboardRepository` зарегистрирован в фабрике как driver `http`; для его активации достаточно изменить `storage.driver`, настроить секцию `api` и предоставить соответствующий backend. Сам production backend в демо отсутствует.

Идеи дальнейшей централизации настроек и другие возможные улучшения вынесены в [BACKLOG.md](BACKLOG.md).

## Визуальная система и доступность

Общие дизайн-токены находятся в `assets/css/base.css`: палитра, семейства Roboto/Inter/Roboto Condensed, размеры контролов, радиусы, тени, фокус и анимации. Страницы используют эти переменные без CSS-фреймворка. Интерфейс спроектирован desktop-first для ширины 1024–1920 px; блокирующее предупреждение о минимальном размере окна показывается только ниже 500 px.

Список и редактор имеют стабильные loading, empty, error, disabled и busy-состояния. Интерактивные элементы поддерживают `hover`, `active`, `focus-visible`, выбранное состояние и доступные подписи. Фокус обозначается тонкой внутренней обводкой без изменения внешних размеров контролов и без тяжёлых внешних колец. Диалоги удерживают клавиатурный фокус, уведомления озвучиваются через live regions, а фиксированный статус сцены в правой части top bar различает загрузку, несохранённые изменения, сохранение, успешное сохранение и ошибку. На ширине до 1180 px статус сворачивается до индикатора без layout shift, сохраняя полное сообщение в `title` и live region.

## Модель данных

Источником истины редактора является независимый JSON-документ:

```json
{
  "schemaVersion": 2,
  "pages": [
    {
      "id": "page-id",
      "name": "Лист 1",
      "canvas": { "width": 1600, "height": 1000, "background": "#ffffff" },
      "elements": []
    }
  ]
}
```

Каждый лист имеет собственные холст и стек элементов. Активный лист относится к UI state и не хранится в документе или DOM. Документы schemaVersion 1 автоматически мигрируют в schemaVersion 2 с одним листом. Konva отвечает только за отображение и взаимодействие.

Доступ к данным идёт через асинхронный `MoodboardRepository`. `IndexedDbMoodboardRepository` использует хранилища `moodboards` и `assets`, проверяет ревизии при сохранении и возвращает независимые копии записей. Runtime `HttpMoodboardRepository` реализует тот же контракт через `ApiClient`; фабрика выбирает адаптер без изменения списка и редактора.

Пользовательские настройки редактора изолированы в `MoodboardSettingsRepository`. Текущий `LocalStorageMoodboardSettingsRepository` хранит сетку, белый лист, snap, линии привязки, показ размеров выделения, тёмный и фокус-режимы, а также выбранную толщину ручного ластика в версионированной записи отдельно для каждого `userId`. Для гостя используется отдельный scope; повреждённые значения нормализуются, прежний общий ключ настроек мигрируется. Запрет `localStorage` не блокирует редактор: значения продолжают работать в памяти текущей сессии.

## Каркас редактора

Редактор разделён на независимые модули:

- `EditorApp` загружает доску, связывает модули и сохраняет изменения;
- `EditorStore` отдельно хранит JSON-документ и UI state;
- `CommandManager` выполняет изменения документа, а `HistoryManager` хранит undo/redo;
- `CanvasAdapter` полностью строит Konva-сцену из документа;
- `ViewportController` управляет zoom, fit и pan;
- `UIController` связывает панели и горячие клавиши с командами.

Konva-сцена состоит из background, content и UI layers. Во время drag/transform меняется только Konva node, а итоговые координаты и размеры записываются в JSON-документ после завершения действия. Масштаб и положение viewport никогда не сохраняются в документе.

Рабочая область поддерживает zoom колесом в диапазоне 10–500%, панорамирование СКМ, `Space + drag` и инструментом «Рука». Если после панорамирования все объекты активного листа оказываются за пределами видимой области, слева сверху появляется кнопка «Назад к содержимому»: она возвращает центр viewport к общей рамке объектов и подбирает масштаб, чтобы даже далеко разнесённые элементы снова оказались в фокусе. На пустом листе и пока виден хотя бы один объект кнопка скрыта. Название проекта редактируется в popover «Настройки»: `Enter` или потеря фокуса сохраняют изменённое значение, `Escape` возвращает прежнее. В левом нижнем углу расположен навигатор: он показывает текущий масштаб, миниатюры элементов и видимую область; клик, drag и стрелки на миникарте перемещают viewport. Кнопка `?` справа открывает русскоязычную справку по горячим клавишам без переключателя языка.

Внизу по центру расположена плавающая Action Panel из девяти инструментов: изображение, фигуры, текст, кисть, стрелка/линия, фрейм, дополнительные элементы, выбор и рука. Изображение (включая drag-and-drop), все 14 фигур, текст, кисть, стрелка/линия, фрейм, стикер, выделитель, выбор и рука подключены к редактору. Меню доступны по клику, наведению мышью и с клавиатуры.

Фигура, текст и стикер не появляются автоматически в центре: после выбора инструмента пользователь кликает в нужной точке для создания объекта минимального размера либо протягивает область для задания собственного размера. Во время жеста показывается стабильный preview, для фигур сохраняются исходные пропорции пресета. Новый текстовый блок создаётся пустым и сразу открывает inline-поле ввода; существующий текст редактируется двойным кликом. `Escape` отменяет ввод, `Ctrl/Cmd+Enter` сохраняет его, а клик вне поля сохраняет текст и снимает выделение; все изменения проходят через историю и autosave. После успешного создания, а также после одного штриха кисти/выделителя, стрелки, фрейма или загрузки изображения редактор возвращается в режим «Выбор», выделяет новый объект и показывает его toolbar. Клавиша `Q` включает фиксацию инструмента: фигуры, кисть, выделитель, стрелка и фрейм остаются активными для повторного создания. Escape отменяет режим размещения.

Над одиночным selection показывается типовой toolbar: для изображения доступны ИИ-удаление фона, ручной ластик, отражения по ширине/глубине, lock, замена ресурса и ссылка на товар; для фигуры — заливка, обводка, пипетка, четыре толщины рамки, прозрачность и внешний URL; для текста — цвет, пипетка, размер шрифта от 8 до 240, пять шрифтовых пресетов и три варианта выравнивания; для кисти и выделителя — цвет и толщина, дополнительно для выделителя — прозрачность; для стикера — текст, фон, цвет текста и внешний URL. Общие Z-index, duplicate и delete остаются справа. Связанные изображения, фигуры и стикеры получают UI-индикатор `↗`; toolbar и индикатор не входят в экспорт. Поле `cornerRadius` изображений поддерживается схемой и renderer для совместимости, но отдельная настройка скругления в текущем toolbar скрыта. Изменения проходят через `CommandManager`, undo/redo и autosave.

Контекстное меню холста открывается ПКМ. Drag-жест с пустого места рисует рамку и выбирает все пересекающиеся с ней объекты; `Ctrl/Cmd+клик` добавляет объект в группу либо убирает его, а `Ctrl/Cmd+drag` дополняет текущее выделение новой областью. На пустом месте контекстного меню доступны вставка и выбор всех объектов; `Ctrl/Cmd+A` сохраняет все элементы активного листа как групповое selection, показывает общую рамку и отдельный контур каждого объекта. Группу можно переместить перетаскиванием любого выбранного объекта; новые координаты фиксируются одной командой undo/redo. ПКМ по объекту, рамке или пустому промежутку внутри общей области сохраняет выделение и открывает меню всей группы; только ПКМ вне неё переключает меню на холст. Cut/copy/paste, копирование JSON/PNG, экспорт PNG/PDF, Z-index, перенос на другой лист, блокировка, дублирование и удаление применяются ко всей группе. Изменяющие документ команды проходят через `CommandManager`; внутренний clipboard работает даже при запрете системного Clipboard API. `Ctrl/Cmd+V` вне полей ввода также принимает текущее содержимое системного буфера: PNG/JPEG/WebP проходит через обычную обработку и сохраняется в IndexedDB, а простой текст создаётся отдельным текстовым объектом в центре видимой области. Пункт «Вставить» в контекстном меню использует тот же системный буфер, если браузер разрешает чтение по клику; при запрете интерфейс предлагает надёжный вариант с `Ctrl/Cmd+V`. В полях названия и inline-редакторе текста браузерная вставка остаётся стандартной.

Группировка и разгруппировка доступны кнопками над выделением, из контекстного меню и сочетаниями `Ctrl/Cmd+G` / `Ctrl/Cmd+Shift+G`. Вложенность хранится в `groupPath`: новую группу можно собрать из отдельных объектов и целых дочерних групп, а разгруппировка снимает только выбранный уровень. На холсте группа перемещается, пропорционально масштабируется за угловые маркеры и поворачивается общим маркером как единое целое; карта слоёв позволяет выбирать, переименовывать и переупорядочивать каждый уровень отдельно. Copy/paste, duplicate и копирование листа создают для копии новые ID всех уровней, поэтому она не объединяется с оригиналом. Команды Alt+W/V/S/A/H/D выравнивают selection, сохраняя внутреннее расположение постоянных групп и содержимого фреймов.

## Изображения

Редактор принимает JPEG, PNG и WebP через выбор файлов, drag-and-drop или вставку из системного буфера обмена. Перед записью проверяются MIME-тип, размер файла и фактические размеры изображения. Изображения со стороной больше 2800 px уменьшаются в браузере и только затем сохраняются как Blob через repository.

JSON-документ хранит `assetId`, размеры, трансформацию и признак однократного ИИ-удаления фона `backgroundRemoved`. Blob остаётся в IndexedDB и может использоваться несколькими листами. Изображения можно перемещать, пропорционально масштабировать, вращать, удалять, дублировать и заменять через меню «Дополнительные инструменты». Замена меняет только ресурс и его исходное соотношение сторон: текущие размер, позиция, поворот, ссылка, блокировка и порядок слоя сохраняются; операция входит в undo/redo и autosave. Экспорт активного листа создаёт PNG или PDF без Transformer и UI-слоёв. Область экспорта рассчитывается по общей рамке всех элементов сцены с безопасным отступом, независимо от границ белого листа, поэтому объекты за его пределами не обрезаются. Только пустая сцена экспортируется в размере виртуального холста.

Декодированные изображения кэшируются по `assetId` на время работы редактора. Повторная отрисовка документа после перемещения, трансформации, изменения свойств или undo/redo сразу использует готовый `HTMLImageElement`, не показывает промежуточный placeholder и не перечитывает неизменённый Blob из IndexedDB. Первичная загрузка разных изображений выполняется независимо; устаревшее поколение сцены не создаёт повторную последовательную очередь.

## Текст и фигуры

Новые фигуры записываются как `type: "shape"`. Нижняя панель создаёт квадрат, круг, ромб, треугольник, звезду, овал, шестиугольник, облако, четыре направления стрелок и чекбоксы X/V. Все варианты остаются векторными, поддерживают выделение, перемещение, изменение размера, вращение, слои, undo/redo и экспорт. Старые документы с `type: "rectangle"` продолжают открываться и преобразуются в новый формат при изменении свойств фигуры.

Инструмент «Кисть» создаёт векторный объект `type: "brush"` от нажатия до отпускания указателя. Координаты штриха нормализуются относительно его bounding box, поэтому объект можно перемещать, масштабировать и вращать без потери качества. Доступны цвет и четыре толщины линии; пробел и средняя кнопка мыши временно возвращают панорамирование.

«Стрелка / Линия» создаёт объект `type: "arrow"` drag-жестом от начальной до конечной точки. После выделения доступны три маркера: начало, управляющая точка изгиба и конец. Средняя точка формирует плавную квадратичную кривую и автоматически возвращается в середину прямой при приближении к ней. Начальная и конечная точки примагничиваются к четырём сторонам изображений, текста, фигур, стикеров и фреймов, после чего следуют за перемещением, resize и поворотом цели. Для линии настраиваются HEX-цвет, четыре толщины и независимое оформление обоих концов: без стрелки, заполненная стрелка типа 1 или контурная стрелка типа 2.

«Выделитель» использует тот же векторный механизм и создаёт полупрозрачный объект `type: "highlighter"` поверх текущего содержимого. Доступны четыре толщины, цвет и прозрачность 15–50%; рисование работает по всей рабочей области, включая пространство за белым листом. «Стикер» создаёт `type: "sticker"` с редактируемым текстом, цветным фоном, отдельным цветом текста и необязательной HTTP(S)-ссылкой. Оба типа поддерживают transform, слои, duplicate/delete, undo/redo, autosave, preview и экспорт.

«Фрейм» включает режим рисования контейнера `type: "frame"`: пользователь зажимает основную кнопку мыши в любой точке рабочей области и задаёт прямоугольник drag-жестом. Во время жеста показывается временный preview, а объект создаётся только после отпускания указателя; слишком короткий жест отменяется. Объекты, центр которых находится внутри его границ, получают `frameId`; привязка обновляется при создании, перемещении и resize фрейма, а также при переносе обычного объекта внутрь, наружу или между фреймами. Перетаскивание фрейма перемещает всё его содержимое одной командой истории. В меню «Дополнительные инструменты» toolbar фрейма доступны цвет и прозрачность экспортируемого фона, checkbox обрезки вложенных объектов по его границам и направляющая сетка на 2, 3, 4, 6 или 12 колонок; сетка не попадает в preview и экспорт. Обычное удаление фрейма удаляет контейнер вместе с содержимым, а «Убрать фрейм» в toolbar и контекстном меню удаляет только рамку и очищает `frameId` у объектов.

Состояние выбранного элемента хранится в `EditorStore`; отдельная боковая панель свойств скрыта, а основные настройки перенесены в toolbar над selection. Создание, изменение, перемещение, трансформация, удаление и дублирование проходят через `CommandManager`; свойства Konva (`scaleX`, `scaleY`, `draggable` и другие) в JSON-документ не попадают.

## Слои и объектные команды

Порядок слоёв полностью определяется индексом элемента в `page.elements`: первый элемент находится сзади, последний — спереди. `EditorCommandRegistry` объединяет команды перемещения на один слой или до края, группировки, выравнивания, дублирования и удаления, включая пакетные операции над multi-selection. Дубликат вставляется непосредственно над оригиналом и не переносится автоматически на передний план; копии групп и фреймов сохраняют относительный порядок участников и положение относительно внешних слоёв. Выравнивание сохраняет внутреннее расположение постоянных групп и перемещает содержимое фрейма вместе с ним. Реестр проверяет selection, блокировку и границы массива до создания команды, сохраняет selection после перестановки, выбирает созданные дубликаты и снимает selection после удаления.

Карта слоёв показывает активный лист как доступное дерево с группами и фреймами и обновляется вместе со сценой. Клик выбирает объект или ветку на холсте, ПКМ открывает те же объектные команды, а drag-and-drop меняет Z-index на корневом уровне и внутри групп/фреймов. Поиск учитывает имя, тип, текст, URL и название родительского фрейма; фильтры типа и принадлежности к фрейму находятся в сворачиваемом блоке «Навигация по слоям», который по умолчанию закрыт. Ветки можно сворачивать, слои и группы — переименовывать двойным кликом, кнопкой или `F2`, а блокировку ветки можно менять одной кнопкой. Вверху всегда видны счётчики всех, выбранных и заблокированных объектов. Карта остаётся открытой при работе со сценой и закрывается повторным нажатием своей кнопки; открытие справки закрывает карту. Переименование, блокировка и перестановка проходят через `CommandManager`, undo/redo и autosave.

## Листы

Переключатель в верхней панели показывает все листы текущего мудборда. Лист можно создать, скопировать вместе с элементами, переименовать и удалить после подтверждения; последний лист удалить нельзя. В одном мудборде допускается не более 40 листов: при достижении лимита создание и копирование становятся недоступны. Идентификаторы элементов при копировании создаются заново, а изображения безопасно ссылаются на существующие `assetId`. Все операции с листами проходят через `CommandManager`, входят в undo/redo и сохраняются общим autosave документа. История содержимого изолирована по листам: переключение листа переключает доступные undo/redo, а откат на одном листе не заменяет содержимое остальных.

## История и клавиатура

`HistoryManager` хранит в памяти до 100 операций на каждый лист и никогда не записывается в IndexedDB. Запись истории содержит снимки только изменённых листов и при undo/redo объединяется с актуальным документом, поэтому данные других листов не откатываются. Межлистовые операции регистрируются в стеках всех участвующих листов и выполняются только когда являются последними в каждом из них — это защищает более новые правки целевого листа от перезаписи. Drag и transform фиксируются только на `dragend` и `transformend`, редактирование полей — событием `change`. Selection, viewport и autosave не создают операции истории; новое изменение после undo очищает redo затронутого листа, а связанную межлистовую запись согласованно удаляет из всех её стеков.

Редактор поддерживает Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl/Cmd+Y, Ctrl/Cmd+C/X/V/A/D/U/P/G, Ctrl/Cmd+Shift+G, Delete/Backspace и Escape. Ctrl/Cmd+P экспортирует активный лист в PDF. Инструменты включаются клавишами `V` (выбор), `H` (рука), `R` (прямоугольник), `O` (овал) и `F` (фрейм), `Q` переключает их фиксацию. Ctrl/Cmd+= и Ctrl/Cmd+− меняют масштаб, Shift+0 устанавливает 100%, Shift+1 и Ctrl/Cmd+0 вписывают холст, Shift+2 масштабирует к selection, Ctrl/Cmd+' переключает сетку. Ctrl/Cmd+/ включает тёмный режим, Ctrl/Cmd+. — фокус-режим, `Escape` выходит из него. Стрелка вверх/вниз переносит selection на передний/задний план, Shift+стрелка вверх/вниз перемещает его на один слой; Shift+H/V отражают выбранное изображение по ширине/глубине, а Alt+W/V/S/A/H/D выравнивают выбранные объекты. Буквенные сочетания распознаются по физическим кодам клавиш и работают при русской раскладке. Во время ввода в `input`, `textarea`, `select` или `contenteditable` объектные команды не перехватывают клавиатуру; Escape только завершает редактирование текущего поля.

## Autosave и восстановление

При каждом изменении JSON-документа редактор синхронно обновляет аварийный черновик в `localStorage`, не дожидаясь debounce и транзакции IndexedDB. Черновик содержит идентификатор доски, базовую revision, время изменения и последнюю несохранённую версию документа; Blob изображений остаются в IndexedDB и по-прежнему подключаются через `assetId`. После устойчивого сохранения черновик удаляется. Если вкладка или браузер завершились раньше, при следующем открытии появляется блокирующее уведомление с выбором: восстановить изменения либо удалить черновик. Повреждённые и устаревшие черновики отбрасываются автоматически и не перекрывают более новую revision из repository.

Во время активной записи содержимого через текущий repository обработчик `beforeunload` запрашивает у браузера подтверждение закрытия страницы. При обычном ожидании debounce предупреждение не показывается: аварийная копия уже находится в `localStorage`. События `visibilitychange` и `pagehide` дополнительно запускают немедленный `flush`, насколько это позволяет жизненный цикл вкладки.

`AutosaveManager` получает снимки документа только через `EditorStore` и сохраняет их через интерфейс repository с debounce 1200 мс. Одновременно выполняется не более одной записи; изменение во время активной транзакции ставит следующий снимок в очередь. Успешное сохранение обновляет локальную `revision`. Временные локальные сбои, network/timeout и HTTP `408`, `425`, `429`, `500`, `502`, `503`, `504` запускают retry с увеличивающейся задержкой и поддержкой `Retry-After`; ошибки авторизации, валидации, CSRF, `404`, `409` и отменённые запросы автоматически не повторяются.

Popover «Настройки» рядом с экспортом содержит переименование проекта и две группы параметров. В «Настройках сцены» находятся сетка, белая подложка и постоянное примагничивание; в «Расширенных настройках» — линии привязки, размеры выделения в пикселях, тёмный и фокус-режимы. Линии привязки, размеры, тёмный и фокус-режимы по умолчанию выключены. Направляющие ищут подходящие объекты в пределах 720 экранных пикселей независимо от zoom. «Всегда привязывать объекты» использует радиус обнаружения 8 экранных пикселей и корректирует координаты перемещения/resize. При выключенной привязке линии появляются только при фактическом совпадении точек с допуском 0,5 экранного пикселя, поэтому остаются перпендикулярными и не отрываются от объекта. Snap продолжает работать при скрытых линиях, а линии можно показывать при выключенном snap. Расчёт учитывает поворот, не меняет геометрию при отражении содержимого и поддерживает изображения, текст, фигуры, стикеры, фреймы, кисть, выделитель и стрелки. В фокус-режиме в правом верхнем углу остаётся приглушённая кнопка выхода с подсказкой `Esc`; при наведении и клавиатурном фокусе она становится контрастнее. Название сохраняется через repository досок, а визуальные настройки — через repository пользовательских настроек и не попадают в JSON-документ. Скрытие белой подложки влияет только на рабочую область: preview и PDF сохраняют фон документа, а PNG всегда экспортируется прозрачным.

Undo и redo генерируют обычное событие изменения документа и поэтому также сохраняются. Selection, viewport и промежуточные события Konva не запускают autosave. При `visibilitychange`, `pagehide`, `beforeunload` и явном уничтожении редактора ожидающий снимок принудительно передаётся repository. После открытия редактор загружает последний устойчивый документ и revision из repository.

## Страница списка

`index.php` загружает записи через `MoodboardRepository`, сортирует их по `updatedAt` и отображает preview или безопасный placeholder. Для IndexedDB используется `previewBlob`, для HTTP — серверный HTTP(S) `previewUrl`; локальный Blob имеет приоритет. Ошибка загрузки URL автоматически возвращает штатный placeholder. Кнопка создания всегда остаётся первой; имя новой пустой доски строится как «Новый проект N», где N равно текущему числу проектов плюс один. Активные доски можно создать, открыть, переименовать, дублировать, поделиться ссылкой и перенести в расположенный на той же странице архив. Архивную доску нельзя редактировать: её можно восстановить либо безвозвратно удалить после подтверждения. Пользовательские названия всегда вставляются в DOM через `.text()`.

Кнопка «Создать из шаблона» открывает доступный modal-каталог из восьми карточек: четыре импортированные заготовки и по одному их варианту. Выбор создаёт обычный JSON-документ через `MoodboardRepository.create()` и сразу открывает его в редакторе; элементы и листы остаются редактируемыми. Каталог учитывает тарифный лимит и блокирует повторное создание, пока операция не завершена.

## Публичная ссылка и гостевой просмотр

Команда «Поделиться проектом» в меню карточки и пункт «Создать публичную ссылку» в меню экспорта редактора сохраняют последние правки и копируют ссылку `/moodboards/view.php?token={token}`. Гостевой экран не выполняет тарифную блокировку, скрывает сетку и все инструменты редактирования, но позволяет переключать листы и экспортировать PNG, PDF активного листа и многостраничный PDF при наличии минимум двух заполненных листов. Viewer открывается в режиме «Рука», поддерживает zoom и pan. В верхней панели остаются название доски, переключатель листов, экспорт, кликабельный логотип RoomPlan и кнопка «Войти» либо «Аккаунт» в зависимости от текущей авторизации. Отдельный `Link_project` в редакторе и viewer скрыт.

Это демонстрационный контракт без production backend: идентификатор доски пока используется как локальный read-only token, но viewer видит его только через `LocalPublicMoodboardRepository` и не получает приватный repository. Поэтому ссылка открывается только на том же origin и в том же профиле браузера, где хранится доска; на другом устройстве, в другом браузере или в приватном окне данных не будет. Production-интеграция переключает `publicViewer.driver` на `http`: `HttpPublicMoodboardRepository` получает очищенный snapshot и token-scoped assets без session cookies. Сам backend, выдача и отзыв криптографического token в демо не реализованы.

## Preview и экспорт

После устойчивого autosave `PreviewManager` выбирает активный заполненный лист либо первый заполненный лист проекта, вписывает область всех его объектов в кадр 16:10 с отступом и сохраняет PNG размером не более 480×300 через repository. Пустой белый лист без объектов не считается содержимым. Если заполненных листов нет, preview очищается и карточка показывает штатный дефолт нового проекта. Preview рендерится на отдельном скрытом canvas, поэтому выбор другого листа не переключает рабочую область и не вызывает мигание. Повторные запросы объединяются, поэтому preview не генерируется на `dragmove` или каждое движение мыши. Страница списка освобождает только созданные ею object URL для локальных Blob; серверные `previewUrl` не отзываются.

Экспорт активного листа рассчитывает общую рамку всех объектов с безопасным отступом и не зависит от текущих zoom, pan или границ белой подложки; для пустого листа используется его виртуальный размер. PNG создаётся с прозрачным фоном, PDF — из JPEG с фоном документа и фиксированным масштабом относительно виртуального холста, поэтому объекты не растягиваются на всю страницу. Пункт «Все листы в PDF» появляется динамически, когда в документе есть минимум два заполненных листа, и создаёт отдельную страницу для каждого такого листа в порядке документа; пустые листы пропускаются. Те же варианты доступны в гостевом просмотре. Перед снимком ожидаются изображения и шрифты, UI layer с Transformer и направляющая сетка фреймов скрываются, а состояние Konva Stage и слоёв восстанавливается сразу после создания export canvas.

## E2E baseline

Playwright содержит 12 критических сценариев: создание и повторное открытие доски, операции с листами, загрузку изображения, resize и групповое перемещение, undo/redo, autosave с reload, PNG/PDF, публичный просмотр, ручной ластик, перенос проекта через JSON, маркеры новой стрелки и расширенные функции фрейма. Каждый тест запускается в новом браузерном контексте с изолированной IndexedDB и дополнительно проверяет отсутствие необработанных JavaScript-ошибок и падений локальных запросов `/moodboards/`.

Установка dev-зависимости и Chromium выполняется один раз:

```bash
npm install
npx playwright install chromium
```

Основной локальный прогон:

```bash
npm run test:e2e
```

Playwright сам запускает PHP-сервер на `127.0.0.1:4173` из родительского каталога. По умолчанию используется комплектный `../.tools/php-8.4.24/php.exe`, а другой PHP можно передать через `MOODBOARDS_PHP_BINARY`. Если пароль демонстрационной оболочки изменён, задайте `MOODBOARDS_DEMO_PASSWORD`; fallback для текущего демо — `demo123`.

Для локальной матрицы Chrome, Edge и Firefox сначала установите Firefox, затем запустите:

```bash
npx playwright install firefox
npm run test:e2e:browsers
```

Отчёт, trace, видео и скриншоты падений создаются в `playwright-report/` и `test-results/`; эти каталоги не попадают в Git.

## Smoke test repository

Откройте `/moodboards/repository-smoke-test.php`. Тест использует отдельную временную IndexedDB и проверяет:

- создание, чтение, список и изменение метаданных;
- архивирование, блокировку редактирования и восстановление;
- сохранение после закрытия и повторного открытия базы;
- обновление версии схемы;
- миграцию schemaVersion 1 в многостраничную schemaVersion 2;
- сохранение документа с контролем ревизий;
- запись и чтение Blob изображения и превью;
- дублирование документа вместе с ассетами;
- сохранение и дублирование нескольких листов;
- удаление и каскадную очистку ассетов;
- отсутствие частичных записей после ошибок;
- корректную пустую запись и детерминированную ошибку `CORRUPT_RECORD` для повреждённой записи;
- очередь autosave после серии быстрых изменений;
- документ со ссылкой на отсутствующий asset.

Тестовая база удаляется после завершения и не затрагивает пользовательские данные.

Smoke test проверяет слой данных и не заменяет интерактивный E2E. Финальный сценарий создания, редактирования, reload, экспорта, preview, duplicate/delete и матрица Chrome/Edge/Firefox находятся в [acceptance checklist](docs/ACCEPTANCE-CHECKLIST.md).
